# ระบบตรวจสอบวุฒิที่โรงเรียนส่งกลับ ด้วย AI (ขั้นที่ 3–10)

โปรแกรมเดสก์ท็อปที่ทำงานแทนคนใน lane **ระบบอัตโนมัติ (AI / RPA)** ของ To-Be Flow
คือรับไฟล์ที่โรงเรียนต้นสังกัดส่งกลับ → อ่านด้วย AI → ตรวจตามกฎ → บันทึกเข้า SCMS
โดยเคสที่ไม่ผ่านเกณฑ์จะเข้าคิวให้เจ้าหน้าที่ยืนยัน (human-in-the-loop)

## เอกสารที่ระบบอ่าน

"บัญชีรายชื่อนักศึกษา — ขอตรวจสอบวุฒิ" ที่มหาวิทยาลัยส่งไปให้โรงเรียน แล้วโรงเรียนกาผลกลับมา

* **หัวเอกสาร** — ที่ มหป.(ตทน) …/…, ชุดที่ …, ชื่อโรงเรียน/สถาบัน + รหัสสถาบัน
* **ตาราง** — ลำดับ | รหัสนักศึกษา | ชื่อ-สกุล | คณะ/วิทยาลัย | ผลตรวจ 3 กลุ่ม | หมายเหตุ
  * การสำเร็จการศึกษา → สำเร็จ / ไม่สำเร็จ
  * วันที่สำเร็จในเอกสาร → ถูกต้อง / ไม่ถูกต้อง
  * วุฒิฯ ที่สำเร็จในเอกสาร → ถูกต้อง / ไม่ถูกต้อง
* **ท้ายเอกสาร** — ลายมือชื่อผู้ตรวจสอบ 1 จุด + ชื่อในวงเล็บ + ตำแหน่ง

ไม่มีเลขบัตรประชาชน และไม่มีลายเซ็นรายแถว — อ้างตัวบุคคลด้วย **รหัสนักศึกษา** เท่านั้น

## เกณฑ์ Auto-Post (ขั้นที่ 7)

บันทึกเข้า SCMS อัตโนมัติได้ต่อเมื่อครบทุกข้อ ไม่ครบข้อใดข้อหนึ่งจะเข้าคิวให้เจ้าหน้าที่

1. เป็นแบบฟอร์มของมหาวิทยาลัย
2. มีลายมือชื่อผู้ตรวจสอบท้ายเอกสาร และอ่านชื่อในวงเล็บได้
3. ทุกแถวกาครบทั้ง 3 กลุ่ม และเป็นผลบวกทั้งหมด (สำเร็จ / ถูกต้อง / ถูกต้อง)
4. ไม่มีหมายเหตุที่ส่อว่าปลอมแปลง
5. confidence ทุกแถว ≥ เกณฑ์ และชื่อตรงกับรหัสนักศึกษาใน SCMS

### กฎที่ปิดไม่ได้

* ฟอร์มที่ไม่ใช่ของมหาวิทยาลัย → ไม่ผ่านเกณฑ์ทันที ส่งเจ้าหน้าที่ตรวจ 100%
* หมายเหตุที่ระบุการปลอมแปลง → ห้าม Auto-Post ต้องส่งนิติการเสมอ
* ทุกค่าที่บันทึกเก็บคู่กับ AI raw value, confidence, source page, edited flag

### กันการอ่านช่องผิดข้าง (ความเสี่ยงหลักของงานนี้)

การกาช่อง "ไม่สำเร็จ / ไม่ถูกต้อง" อยู่ติดกับช่องบวก อ่านพลาดข้างเดียวแปลว่าเอกสารปลอม
กลายเป็นผ่าน จึงมีกันไว้ 3 ชั้น

1. พร็อมท์บังคับให้ตัดสินจากตำแหน่งแนวนอนของเครื่องหมายเทียบเส้นแบ่ง และห้ามลอกแถวก่อนหน้า
2. อ่านช่องผลตรวจซ้ำรอบสอง (`verify_marks`) — สองรอบไม่ตรงกัน = `unclear` = เข้าคิว
3. กฎ: มีหมายเหตุแต่ผลตรวจเป็นบวกทั้งหมด = ขัดแย้งกัน ต้องให้เจ้าหน้าที่ยืนยัน

## ติดตั้ง

```bash
python3 -m pip install -r requirements.txt
cp .env.example .env      # ใส่ GEMINI_API_KEY (และ MySQL ถ้ามี)
```

ไม่ใส่ค่า MySQL ก็ใช้ได้ — ระบบจะใช้ SQLite ที่ `~/.ai_verification/app.db` แทน

## ใช้งาน

### แบบเว็บ (React + TypeScript) — แนะนำ

เปิด 2 เทอร์มินัล:

```bash
uvicorn app.server:app --reload --port 8000     # เทอร์มินัลที่ 1: backend (FastAPI)
cd frontend && npm install && npm run dev       # เทอร์มินัลที่ 2: frontend (Vite)
```

เปิดเบราว์เซอร์ที่ URL ที่ Vite แจ้ง (ปกติ `http://localhost:5173`) — อัปโหลดไฟล์เอกสารผ่านหน้า
"ประมวลผลเอกสาร" แทนการเลือกโฟลเดอร์ในเครื่อง

### แบบเดสก์ท็อป (เดิม)

```bash
python3 main.py                     # เปิดหน้าต่างเดสก์ท็อป (pywebview)
python3 web/index.html              # เปิดไฟล์ UI ตรง ๆ = โหมดสาธิต ข้อมูลจำลอง
```

แบบไม่มีหน้าจอ:

```bash
python3 cli.py --source data/Inbox                 # รันทั้งโฟลเดอร์
python3 cli.py --provider mock                     # ไม่เรียก API จริง
python3 cli.py --provider gemini --model gemini-3.1-flash-lite
python3 cli.py --queue                             # ดูคิวที่รอเจ้าหน้าที่
python3 cli.py --confirm 3                         # ยืนยันเคส 3 เข้า SCMS
python3 cli.py --reject 5                          # ส่งกลับโรงเรียน
python3 cli.py --runs                              # ประวัติรอบทำงาน
python3 cli.py --live                              # ปิด dry-run ยิง SCMS จริง
```

ไฟล์ทดสอบและวัดผล:

```bash
python3 tools/make_samples.py --count 8   # สร้าง PDF ตัวอย่าง + ทะเบียนอ้างอิง + ground truth
python3 tools/eval_accuracy.py            # วัดความแม่นยำรายฟิลด์ → eval_report/eval_data.csv
python3 -m unittest discover -s tests     # ทดสอบกฎการตัดสิน
```

## ผลทดสอบล่าสุด

เอกสารตัวอย่าง 8 ชุด (63 แถว) ด้วย `gemini-3.1-flash-lite` เทียบ ground truth:

| ฟิลด์ | ความแม่นยำ |
| --- | --- |
| ชนิดฟอร์ม / ลายมือชื่อผู้ตรวจสอบ | 100% |
| รหัสนักศึกษา / คณะ / หมายเหตุ | 100% |
| ชื่อ-สกุล | 81% (พลาดสระ-วรรณยุกต์) |
| ผลตรวจ 3 กลุ่ม | 86% / 81% / 98% |
| **รวม** | **92.4%** |

ระดับเอกสาร: **เคสที่ต้องให้คนตรวจหลุดเป็น Auto-Post = 0 จาก 8** (ชั้นกันการอ่านผิดข้างทำงาน)
ราคาที่จ่ายคือเอกสารสะอาดบางชุดถูกส่งเข้าคิวด้วย — ตั้งใจให้พลาดไปทางปลอดภัย

โมเดลอื่นที่ลองแล้ว: `gemini-2.5-flash` ได้ 88.4% (แย่กว่า) จึงตั้งค่าเริ่มต้นเป็น `gemini-3.1-flash-lite`
