# Prototype ระบบตรวจสอบวุฒิที่โรงเรียนส่งกลับ

เว็บสาธิตสำหรับนำเสนอขั้นตอนรับเอกสาร อ่านผลด้วย AI ส่งเคสเข้าคิวเจ้าหน้าที่ และแสดงประวัติการทำงาน **ทุกข้อมูลเป็นข้อมูลสมมติ** การกดประมวลผลและยืนยันผลจำลองในเบราว์เซอร์ ไม่มีการเรียก Gemini, SCMS หรือ backend และไม่มีการส่งไฟล์ที่เลือกไปยังเซิร์ฟเวอร์

## ทดลองบนเครื่อง

ต้องมี Node.js 22 ขึ้นไป:

```bash
npm ci
npm run dev:web
```

เปิด URL ที่ Vite แสดง ปกติคือ `http://localhost:5173` หน้าหลักเริ่มจากรายการชุดเอกสารตัวอย่าง 8 ชุด รวมไฟล์ตัวอย่างของโรงเรียนที่สำเร็จและโรงเรียนที่ต้องติดตาม การ์ดด้านบนสรุป **โรงเรียนทั้งหมด / โรงเรียนที่สำเร็จ / โรงเรียนที่พบปัญหา / โรงเรียนที่ต้องติดตาม** กดการ์ดแล้วจะเห็นรายชื่อโรงเรียน จำนวนชุดเอกสารของแต่ละโรงเรียน และสถานะในหมวดนั้น กด **เริ่มประมวลผล** เพื่อแสดงผลลัพธ์จำลองใหม่ กด **อัปโหลด** เพื่อเลือกไฟล์ PDF จากเครื่องได้ทันที หรือวางโฟลเดอร์ที่มี PDF ลงในกรอบอัปโหลด เบราว์เซอร์ใช้เพียง *ชื่อไฟล์* สำหรับรอบสาธิตและไม่อ่านเนื้อหาไฟล์

ในหน้าหลัก กดแถวชุดเอกสารเพื่อเปิดรายละเอียดหรือตรวจสอบเคสได้ทันที เมื่อเปิดหมวดโรงเรียนแล้วกดชื่อโรงเรียน จะเห็นรายการไฟล์ของโรงเรียนนั้นเพื่อตรวจนับกับจำนวนชุดเอกสารที่แสดง

หน้าคิวตรวจสอบมี Dropdown **ค้นหาโรงเรียน** เหนือรายการเคส สามารถพิมพ์ชื่อใน Dropdown แล้วเลือกโรงเรียนเพื่อดูเฉพาะเคส หรือเลือก **ทุกโรงเรียน** เพื่อกลับไปดูทั้งคิว

การยืนยันเคสและการตั้งค่าจะเก็บใน `localStorage` ของเบราว์เซอร์นั้นเท่านั้น หากต้องเริ่มข้อมูลสาธิตใหม่ ให้ล้างข้อมูลเว็บไซต์ของโดเมนนี้ในเบราว์เซอร์แล้วโหลดหน้าใหม่

## Deploy บน Netlify

เชื่อม repository นี้กับ Netlify แล้วให้ Netlify อ่าน [netlify.toml](netlify.toml) ที่ root ซึ่งตั้งค่าไว้ดังนี้:

- Build command: `npm run build`
- Publish directory: `apps/web/dist`
- Node.js: 22

ไม่ต้องตั้ง environment variable, database หรือ backend สำหรับ prototype นี้ สามารถ build ในเครื่องด้วย `npm run build` และตรวจโค้ดด้วย `npm run lint`

## โครงสร้าง

```text
apps/web/             เว็บไซต์ React + TypeScript + Vite ที่ deploy บน Netlify
apps/api/             Python API และ pipeline สำหรับระบบจริงในอนาคต (prototype ไม่เรียกใช้)
legacy/desktop/      โค้ดเดสก์ท็อปเดิม เก็บไว้เป็นข้อมูลอ้างอิง
data/                 ข้อมูลทดสอบของ backend ไม่ถูกนำเข้าเว็บ
```

ข้อจำกัดของ prototype: ข้อมูล AI, ลายมือชื่อ, เอกสารจำลอง และ Audit Trail ไม่ใช่ผลตรวจจริง การเปิดเว็บจากอุปกรณ์คนละเครื่องจะมีสถานะและข้อมูลที่บันทึกแยกกัน

## รูปแบบหน้าจอ

ธีมหลักเป็นขาวชมพูตามโทน SPU โดยใช้สีชมพูสำหรับปุ่มและส่วนที่เลือก สีเขียว/เหลือง/แดงยังใช้เฉพาะสถานะเพื่อให้แยกผลตรวจได้ง่าย หน้าหลักแสดงการ์ดสถานะโรงเรียน 4 กล่อง แล้วเปิดรายชื่อโรงเรียนพร้อมจำนวนชุดเอกสารและสถานะเมื่อเลือกหมวด หน้าประมวลผลแสดงการเตรียม PDF สถานะ และผลลัพธ์ หน้าตั้งค่าเหลือเฉพาะโมเดล AI และปุ่มทดสอบ API แบบจำลอง รองรับจอมือถือด้วยเมนูแนวนอนและการจัดคอลัมน์ใหม่
